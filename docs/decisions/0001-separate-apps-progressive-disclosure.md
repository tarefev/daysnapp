# 0001: Отдельные приложения и постепенное раскрытие возможностей

**Статус:** принято
**Дата:** 2026-10-21

## Контекст
Продукт охватывает много сфер жизни: питание, тренировки, финансы, лайфстайл, медиа и другие. Если показать пользователю все возможности сразу, это его перегрузит, и он не поймёт, что за продукт перед ним.

## Варианты
1. Одно приложение-комбайн со всеми модулями сразу.
2. Отдельные приложения, у каждого один основной модуль. Остальные модули подключаются по мере необходимости.

## Решение
Вариант 2. В сторе несколько приложений, у каждого один основной модуль и понятный сценарий. Остальные модули подключаются внутри любого из них. Если подключено всё, получается комбайн. Вход общий во всех приложениях, аккаунт и база данных — одни на все.

## Почему
- Человеку проще начать с одной понятной задачи (например, «сфотографируй еду и узнай калории»), чем разбираться в продукте «для всего».
- Продукт расширяется в ответ на поведение пользователя. Если пользователь присылает контент для неподключённого модуля, приложение предлагает этот модуль подключить.
- Каждое приложение можно продвигать отдельно, под свою аудиторию.

## Последствия
- Каждый модуль — это полноценное приложение по объёму и глубине. Модули делаются постепенно, по одному.
- Общий вход, аккаунт и база проектируются с расчётом на все будущие модули.
- Нужен механизм подключения модулей и, вероятно, платного доступа к ним.
- Открытые вопросы: что происходит с контентом, если пользователь отказался подключать модуль, и как пользователь узнаёт о других модулях. Их решаем позже, см. [discovery.md](../discovery.md).
