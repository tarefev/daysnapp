# daysnapp

Описание проекта лежит в `docs/overview.md`, оглавление документации — в `docs/README.md`.

## Работа с документацией
- Перед задачей по issue проверь, есть ли файл `docs/tasks/<номер>-*.md`. Если нет, заведи его по шаблону `docs/tasks/_template.md` и веди по ходу работы.
- Когда находишь или чинишь баг, заводи или обновляй файл в `docs/bugs/` по шаблону.
- Если меняешь модуль, обнови его описание в `docs/modules/`. Для нового модуля заведи файл.
- Значимое техническое решение (библиотека, архитектура, формат данных) записывай в `docs/decisions/`.
- Новые идеи пользователя складывай в `docs/ideas/`.
- Если поменялись запуск, переменные окружения или деплой, обнови `docs/setup.md` или `docs/deploy.md`.
- Заметные изменения добавляй в `CHANGELOG.md`, в раздел `[Unreleased]`.
- Документацию пишем на русском, имена файлов — латиницей через дефис.
- Секреты и ключи в документацию не пишем никогда, только где они хранятся.

## Git
- Основная ветка — `main`, напрямую в неё не пушим.
- Любые изменения: коммит в рабочую ветку → PR в `main`.
- Мержим PR только когда пользователь об этом попросит: например, «мержи» или «прими сразу». Без такой просьбы PR остаётся открытым.
